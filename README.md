# Roco-dashboard-demo

把上级项目 `Roco-dashboard`（《洛克王国：世界》异色精灵统计看板）里的真实技术链路，拆成若干**可运行的小 demo**，沉淀可复用的抓包、解析与数据派生方案。

> GitHub 仓库：https://github.com/Zane0207/roco-dashboard-demo
> 当前状态：模块 A 实现中。每个 demo 都从真实项目里来，但只保留可公开、可离线运行的部分。

## 项目背景

游戏把精灵资产收在背包里，却没有导出能力。上级项目里一份真实玩家 Miffy 的快照显示：**26 个盒子、593 只精灵，其中 187 只异色、84 只炫彩**。要看「我有哪些异色」「哪个盒子快满了」，只能一页页翻。

数据明明存在，却不可查询。

## 需求

把不可见的游戏数据变成可结构化查询的资产，同时不碰游戏进程、不给每台终端设备增加安装负担，并让数据所有权始终归用户。

## 现有方案

- **Windows Npcap / WinPcap**：每台 PC 装内核态驱动、要管理员权限；受管机器常禁止，且只覆盖那一台设备
- **安卓 / iOS**：VPN 代理要装证书、明文经过第三方进程且可能被 SSL Pinning 拦；root / 越狱则破坏系统沙箱

## 痛点

这些工具都能抓包，但代价落在**每台终端设备**上，而且每机一套配置，时间线对不齐、导出格式不统一。抓包能力是分散的，无法沉淀成统一数据源，上层应用只能重复造轮子。

## 我是怎么解决的

把抓包点搬到**所有设备的网络必经点——路由器**：端点零安装，`br-lan` 上 BPF 严格过滤游戏流量，先落 pcap、离线再解析。这样一份原始数据可以同时派生出背包、战斗、图鉴等多套应用。

底层已在**新路由 D2（Newifi D2）+ Padavan 固件**上验证：Entware 提供 `tcpdump` / `python3`，`/opt` 固定 256MB tmpfs；端点侧零安装。

## 实现中的困难与克服

- 同步解析大帧会拖垮抓包 → 拆成「先抓后解」，抓包只写 pcap
- 会话密钥 `0x1002` 只在建连瞬间下发 → 先开采集，再断网 3 秒重连
- 丢段与 1044 心跳噪声淹没战斗帧 → `gap_timeout` 5s → 10s，实时链路过滤噪声但原始 pcap 完整留档
- 多设备与同 IP 双开 → 按 IP 分发、`game_id` 区分会话
- 固件启动脚本把 `/opt` 打回 40MB → 固化启动脚本与 nvram，并备一键恢复
- 出战栏 / 场景宝箱与背包盒混淆 → 盒位判别式 + 抓包队伍序列还原显示顺序

完整过程见模块 A 的 `README.md`。

## 最终效果

- **数据**：26 盒 / 593 只 / 187 异色 / 84 炫彩，玩家核心资产第一次可查询
- **链路**：PC + iPad + 手机统一采集；一次抓包，多处派生
- **演进**：新增应用只写离线解析器，不再改抓包链路和终端设备
- **安全**：原始帧与密钥不出本机，交付物只有脱敏派生字段
