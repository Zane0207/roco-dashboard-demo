## 1. 观察到的痛点

上级项目 `Roco-dashboard` 里有一份真实玩家 Miffy 的背包快照：

- **26 个盒子、593 只精灵**，其中 **187 只异色、84 只炫彩**
- 游戏内没有「导出背包」能力，玩家要看「我有哪些异色」「哪个盒子快满了」只能一页页翻

这不是「记录效率低」，而是**玩家的核心资产不可查询**——数据明明存在，却只能靠肉眼扫描。

## 2. 我的 idea

不改游戏、不装外挂，在**玩家设备的网络必经点**（路由器）被动读取流量：

1. 在 `br-lan` 上用 BPF 只抓 `tcp port 8195 and host <游戏PC_IP>`
2. 抓包进程零解析、只写 pcap；离线回放时再重组 → 解密 → 按 opcode 门控解析
3. 只输出**派生的 boxes JSON**，原始帧、明文帧、会话密钥一律不进产物
4. 默认不同步，用户显式点击才上传

## 3. 产品经理的三个关键判断

| 判断 | 为什么重要 |
|---|---|
| **被动只读 + BPF 严格过滤** | 合规底线：不发包、不注入、不改内存，把「辅助工具」和「外挂」划清界限 |
| **抓包/解析拆分** | 真实踩过的坑：同步解析大帧会拖垮抓包，导致战斗帧丢失。拆成"先抓后解"后互不干扰 |
| **默认不同步 + 字段白名单** | 数据所有权归用户；契约层不夹带 UID、玩家名、IP、时间戳——隐私最小化是设计约束，不是补丁 |

## 4. demo 里能看到什么

- **链路演示**：6 个可点击节点（旁路抓包 → TCP 重组 → 会话解密 → opcode 门控 → 字段白名单 → 结构化快照），每个节点说明「做了什么 / 为什么这么设计」
- **播放完整链路**：模拟真实抓包日志流，包括「先开采集、再断网 3 秒重连拿密钥」这个真实前提
- **解析结果**：用 Miffy 真实数据渲染 26 个盒子、593 只精灵，可点击盒子查看内部宠物
- **合规提示**：点「同步到云端」会展示脱敏检查清单

## 5. vibecoding 过程（面试可讲）

1. **读真源**：先读上级项目 `ROUTER_CAPTURE_HANDOFF.md` / `M10_CAPTURE_HANDOFF.md`，确认真实链路、opcode、隐私红线，不自己凭空设计
2. **数据准备**：写 `scripts/prepare_miffy_data.py` 从真实快照提取字段、脱敏、生成 `data.js`
3. **原型实现**：单文件 HTML + 内联 CSS/JS，零依赖、打开即用
4. **验证**：node `--check` 语法校验 + 数据完整性/脱敏泄漏检查 + DOM 引用检查
