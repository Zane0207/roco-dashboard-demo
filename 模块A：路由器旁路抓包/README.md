## 1. 问题来源

以真实玩家 Miffy 的账号为例：

- **26 个盒子、593 只精灵**
- 其中 **187 只异色、84 只炫彩**

游戏没有提供导出能力。要确认「有哪些异色」「哪个盒子快满了」，只能逐页浏览。数据已经存在，但不可查询——这是整条链路的起点。

## 2. 目标与边界

将不可见的游戏数据转化为可结构化查询的资产，同时满足三项约束：

- **不接触游戏进程**：不注入、不改内存、不发包
- **不增加终端负担**：PC / iPad / 手机均无需安装驱动或证书
- **数据所有权归用户**：默认不同步，交付物仅含派生字段，原始帧与会话密钥不进入产物

## 3. 行业常见方案

### 3.1 Windows：Npcap / WinPcap 类

- [Npcap](https://nmap.org/npcap/) / [WinPcap](https://www.winpcap.org/) 需要在每台 PC 安装内核态驱动并授予管理员权限；受管机器通常禁止安装，驱动本身也构成高权限攻击面
- 通常配合 [Wireshark](https://www.wireshark.org/) 使用，覆盖范围仅限安装了驱动的那一台设备，换机需重新部署

### 3.2 安卓 / iOS：VPN 代理或 root / 越狱

- [Charles](https://www.charlesproxy.com/)、[HttpCanary](https://httpcanary.cn/) 等代理类工具需要安装证书并开启系统 VPN，明文流量经过第三方进程；应用侧的证书绑定 / SSL Pinning 会阻断抓包，需要额外绕过
- [PCAPdroid](https://github.com/GrenderG/PCAPdroid) 等方案可在不 root 的情况下抓包，但仍需逐设备配置；root / 越狱后使用 [tcpdump](https://www.tcpdump.org/) 则会破坏系统沙箱
- 多设备场景下每机一套配置，时间线对不齐，导出格式也不统一

### 3.3 同场景项目

- [ROCO-Nearby-Pet](https://github.com/Vicuna1277/ROCO-Nearby-Pet)：附近精灵查看工具，能读取游戏内精灵数据，但聚焦单机单端展示
- [roco-pve-viewer](https://github.com/Evenstar-tools/roco-pve-viewer)：PVE 战斗查看器，同样依赖终端侧数据源，不具备跨设备统一采集

## 4. 方案局限

问题不在于「抓不到」，而在于**成本落点与设计目标错位**：

| 维度 | 行业常见方案的问题 |
|---|---|
| 安全性 | 内核驱动需管理员权限；代理需安装证书、明文经第三方进程；root / 越狱破坏沙箱 |
| 多设备 | 每台设备单独安装与配置，时间线对不齐，导出格式不统一 |
| 数据复用 | 工具各自解决单点问题，原始数据无法沉淀为统一数据源，上层应用需重复开发 |

结论：抓包能力分散，而终端设备为每次抓包重复承担成本。

## 5. 技术路径

采用网络旁路采集架构，将抓包点从终端设备迁移至**网络必经点——路由器**：

1. 在 `br-lan` 开启混杂模式，通过 BPF 严格过滤 `tcp port 8195 and host <游戏设备IP>`，仅保留目标设备的游戏流量
2. 采集层零解析、仅落盘 pcap；解析层离线回放，完成 TCP 重组、会话解密与 opcode 门控
3. 会话密钥 `0x1002` 仅在 TCP 建连阶段下发，采集须先于设备重连启动；断网 3 秒重连用于触发密钥下发
4. 输出层仅保留白名单派生字段，原始帧、明文帧与会话密钥不进入交付物，上传默认关闭

底层已验证环境：**新路由 D2（Newifi D2）+ Padavan（老毛子）固件**。Entware 提供 `tcpdump` / `python3`，`/opt` 固定 256MB tmpfs；端点侧零安装。

基于该架构，单份原始采集可派生多类应用：

- **战斗读取**：opcode 4886 战斗帧，按 `battle_mode` / `enter_battle_type` 门控，仅保留有效战斗事件
- **背包管理**：4934 / 6273 / 6275 / 6277 / 6289 解出 PetData 与 PetBox，生成 boxes JSON
- **图鉴收藏**：形态、异色、资质等字段继续派生到图鉴与毕业进度
- 新增上层应用时只需增加离线解析器，**无需改动抓包链路，也无需重新配置终端设备**

架构上的三个关键判断：

| 判断 | 为什么重要 |
|---|---|
| **被动只读 + BPF 严格过滤** | 合规底线：不发包、不注入、不改内存，把「辅助工具」和「外挂」划清界限 |
| **抓包/解析拆分** | 同步解析大帧会拖垮抓包、导致战斗帧丢失；拆成「先抓后解」后互不干扰 |
| **默认不同步 + 字段白名单** | 数据所有权归用户；契约层不夹带 UID、玩家名、IP、时间戳——隐私最小化是设计约束，不是补丁 |

## 6. 关键技术挑战

1. **采集与解析耦合**：实时解析大帧占用抓包进程资源，导致战斗帧 4886 丢失
2. **会话密钥时序约束**：`0x1002` 仅在 TCP 建连瞬间出现，后续流量不重发；采集启动滞后将导致业务帧无法解密
3. **链路丢段与噪声帧**：默认 `gap_timeout=5s` 时 120 秒内 `link_lost` 达 74 次；1044 心跳约 14 条/秒，约 5000 条 ring buffer 在数分钟内被灌满，战斗帧被挤出
4. **多设备与会话隔离**：PC、iPad、手机并行在线；同 IP 双开时仅凭 IP 无法区分会话
5. **路由器运行环境偏移**：Padavan 启动脚本在 USB 重挂时将 `/opt` 从 256MB 回落至 40MB，Entware 与 `python3` 失效
6. **盒位语义歧义**：出战栏不属于背包盒；场景宝箱 24 格与背包盒 30 格混用；协议 `box_id` 顺序与游戏展示顺序不一致

## 7. 应对方案

1. **采集/解析解耦**：抓包进程零解析、只落 pcap，解析完全放到离线回放，两条链路互不干扰
2. **前置采集与重连触发**：先启动采集，再让游戏断网 3 秒重连，确保捕获 `0x1002`
3. **超时调优与分层留档**：`gap_timeout` 由 5s 调整为 10s，`link_lost` 由 74 降至 10、单场战斗 4886 帧稳定到 3；实时链路过滤 1044 心跳等无信息帧，原始 pcap 完整留档，并可通过开关恢复读取被忽略的 opcode
4. **设备分发与会话标识**：通过 `--game-pc-ip` / `--game-ips` 锁定设备；由 opcode 258 解出 profile 中的 `game_id`，用于区分同 IP 双开
5. **环境固化与自恢复**：修改 `Sh01_mountopt.sh`、设置 `nvram size_tmpfs=262144`、在 `started_script.sh` 中 remount，并通过 `mtd_storage.sh save` 写入 flash；另备一键恢复脚本应对意外重挂
6. **盒位判别与顺序还原**：仅接受 `box_id∈[1,200]` 且 `len(pet_gids)==30` 且空位在 `[0,30]` 的背包盒；再从抓包 rawProtocol 的队伍变更帧恢复 3 队 × 6 的 Z 序。109 份历史抓包验证 108 份完全一致、1 份接近

## 8. 结果与价值

- **资产可见性**：以 Miffy 账号为例，还原出 26 盒 / 593 只 / 187 异色 / 84 炫彩，玩家核心资产首次可查询
- **链路复用性**：PC + iPad + 手机统一采集；单份 pcap 可派生战斗、背包、图鉴等多套应用
- **扩展成本**：新增上层应用只需编写离线解析器，不再改动抓包链路与终端配置
- **数据边界**：端点零安装；交付物仅含白名单派生字段，原始帧与会话密钥不出本机

## 9. demo 能力范围

- **入口**：`live.html`，双击即可打开，零依赖、零外网请求
- **链路演示**：6 个可点击节点（旁路抓包 → TCP 重组 → 会话解密 → opcode 门控 → 字段白名单 → 结构化快照），每个节点说明「做了什么 / 为什么这么设计」
- **回放 pcap**：点击「回放 pcap」按钮，左侧按真实项目事件契约滚动输出 `ts / flow_id / dir / opcode / fields / event_kind` 日志，包含 `0x1002` 密钥捕获、1044 心跳过滤、`link_lost` 等真实状态
- **右侧结构化解读**：随回放同步刷新三类目标信息——精灵对战（4886 M5：battle_id / mode / enter_type / 单位资质与异色炫彩位）、背包（4934 / 6273 / 6277 / 6289：26 盒 / 593 只 / 187 异色 / 84 炫彩）、蛋（338 场景 + 579 奖励：蛋 ID / 宠物 / 体重 / 学院窝判定 / 配对时延），另附连接诊断卡
- **解析结果**：用 Miffy 脱敏数据渲染 26 个盒子、593 只精灵，可点击盒子查看内部宠物
- **合规提示**：点「同步到云端」会展示脱敏检查清单；页面不加载原始 pcap、明文帧与会话密钥
