## 1. 背景：现有抓包方案的边界

### 1.1 Windows：Npcap / WinPcap 类

- 要在**每台 PC 上安装内核态驱动**并给管理员权限；受管机器往往直接禁止安装，驱动本身也是高权限攻击面
- 只能看到装了驱动的那一台设备；换一台电脑就要再装一遍、再配一遍

### 1.2 安卓 / iOS：VPN 代理或 root / 越狱

- 代理类工具（Charles、HttpCanary、Stream 等）要装证书、开系统 VPN，明文流量经过第三方进程；App 侧还有证书绑定 / SSL Pinning 检测，经常抓不到或要额外绕过
- root / 越狱后跑 `tcpdump` 会破坏系统沙箱，安全边界和门槛都落在玩家手机上
- **多设备同样是每机一套**：PC、iPad、手机各配各的，时间线对不齐，导出格式也不统一

结论：这些工具都能抓包，但代价落在**终端设备**上——装驱动、装证书、改系统设置，而且无法形成统一的数据源。

## 2. 我的方案：把抓包点放到路由器

路由是家里 PC / 手机 / 平板共用的网络必经点。在 `br-lan` 上旁路抓包：

1. 端点**零安装、零配置、零感知**；不碰游戏进程、不改内存、不发包注入
2. BPF 严格过滤 `tcp port 8195 and host <游戏设备IP>`，只留游戏流量
3. 抓包进程只写 pcap、不做解析；离线回放时再重组 → 解密 → 按 opcode 门控解析
4. 会话密钥 `0x1002` 只在 TCP 建连瞬间下发，因此真实前提是**先开采集，再让设备断网 3 秒重连**
5. 产物只有派生 JSON；原始帧、明文帧、会话密钥不进交付物，默认不同步

## 3. 底层支持：这块路由真的跑得动

已在**新路由 D2（Newifi D2）+ Padavan（老毛子）固件**上验证：

- `br-lan` 开混杂模式，`tcpdump` / libpcap 直接抓桥上流量，不需要厂商 SDK
- `/opt` 挂 Entware，装 `python3` 与采集脚本；tmpfs 固定到 256MB，够放代码与短时缓冲
- 实测多设备同时在线（PC + iPad + 手机），断网重连后可稳定拿到 `0x1002` 并解出盒子数据

> 该固件有启动脚本会在 USB 重挂时把 `/opt` 打回 40MB，已通过启动脚本与 `mtd_storage.sh save` 固化修复。「底层能不能长期跑」是方案能否产品化的分水岭。

## 4. 解决的问题：一次抓包，多处派生

把分散在各终端的抓包能力，收敛成**一个可复用的原始数据源**：

- **战斗读取**：opcode 4886 战斗帧，按 `battle_mode` / `enter_battle_type` 门控，只留真正需要的战斗事件
- **背包管理**：4934 / 6273 / 6275 / 6277 / 6289 解出 PetData 与 PetBox，生成 boxes JSON
- **图鉴收藏**：形态、异色、资质等字段继续派生到图鉴与毕业进度
- 以后加新应用，只新增离线解析器，**不用再动抓包链路，也不用重新配置任何终端设备**

在 Miffy 的真实快照上，这条链路还原出 **26 盒 / 593 只精灵 / 187 异色 / 84 炫彩**——玩家原本只能一页页翻看的核心资产，第一次变成可查询的数据。

## 5. 三个关键判断

| 判断 | 为什么重要 |
|---|---|
| **被动只读 + BPF 严格过滤** | 合规底线：不发包、不注入、不改内存，把「辅助工具」和「外挂」划清界限 |
| **抓包/解析拆分** | 真实踩过的坑：同步解析大帧会拖垮抓包，导致战斗帧丢失。拆成「先抓后解」后互不干扰 |
| **默认不同步 + 字段白名单** | 数据所有权归用户；契约层不夹带 UID、玩家名、IP、时间戳——隐私最小化是设计约束，不是补丁 |

## 6. demo 里能看到什么

- **链路演示**：6 个可点击节点（旁路抓包 → TCP 重组 → 会话解密 → opcode 门控 → 字段白名单 → 结构化快照），每个节点说明「做了什么 / 为什么这么设计」
- **播放完整链路**：模拟真实抓包日志流，包括「先开采集、再断网 3 秒重连拿密钥」这个真实前提
- **解析结果**：用 Miffy 真实数据渲染 26 个盒子、593 只精灵，可点击盒子查看内部宠物
- **合规提示**：点「同步到云端」会展示脱敏检查清单
