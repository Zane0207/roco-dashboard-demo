## 1. 问题来源

一图流截图是玩家社区记录阵容的主要形式，但图上的信息**对机器不可查询**：

- 同一份阵容有 **2 行 3 列** 与 **3 行 2 列** 两种版式，旧逻辑按固定每行 2 个取锚点，必然漏掉第 3 列
- 作者水印会粘进名字框，例如「卡瓦重噜球狼王」，整名匹配直接失败
- OCR 把技能、资质、属性串读成精灵名，weak 补位会把伪行插进 6 格队列，挤掉真名
- 性格有两种表达：模板 A 直接写「平和 / 聪明 / 踏实」，模板 B 只写「物攻 / 魔攻」两个框，需要反查
- 读出来的性格还要和「推荐性格」比对，才能判断这只精灵是否毕业——但**识别事实**和**推荐参考**经常在人工转录里被混为一谈

结果：玩家只能逐图肉眼抄名字、性格、技能，再手工查图鉴和推荐表。

## 2. 目标与边界

把一图流变成可查询的 6 格结构化阵容，同时满足：

- **不上传原图**：demo 只使用真实 OCR 缓存 `dets`（bbox + text + score），页面上的网格是示意图，不是截图
- **不猜游戏事实**：名字靠本地图鉴池归一，性格靠 30 条真值表唯一反查，推荐只读离线缓存
- **识别与推荐分离**：OCR 结果是事实，推荐行是参考；未命中推荐时保留原值，不自动改写
- **离线可复核**：每格保留原始文本、匹配方式、证据 token、技能池命中标记，可整份导出 JSON

## 3. 行业常见方案

### 3.1 人工转录

最准确但不可扩展：每张图逐格抄名字、性格、技能，再查图鉴填 pid。版式一变、水印一粘，人工成本更高。

### 3.2 通用 OCR 直出

腾讯云 / 百度 / 本地 OCR 都能给出文本框，但只认识字、不懂游戏语义：

- 不知道哪 6 个框是精灵名，也不知道行的 Z 序
- 技能框在名字右侧 300–440px，是对称窗口还是非对称窗口，结果完全不同
- 名字错一个字（磨力猫 / 水篮篮）就查不到图鉴

### 3.3 同场景项目

上级项目的 `teamOcr` 云函数已经解决上述语义问题：固定 6 格、名字池真源、性格表反查、技能池过滤，并有两套真实样本 selftest。本 demo 复用它的**结论与字段口径**，不重跑云函数。

## 4. 方案局限

| 维度 | 问题 |
|---|---|
| 版式 | 2 行 3 列与 3 行 2 列混用，锚点、列距、技能归属窗口都要自适应 |
| 噪声 | 水印粘连、属性串 / 资质串伪行、lev 假名都会破坏 6 格队列 |
| 真源 | 名字池若混入队伍名 / 测试名（如「无敌水蓝蓝」），会凭空造出不存在的精灵 |
| 语义 | 增益减益方向决定性格，不能按出现顺序猜；技能池外的 OCR 文本只能留档不能当技能 |
| 推荐 | gradRec 是参考口径，同一形态可能有多条「毕业 / 可用 / 收藏」行，不能只取第一条 |

结论：难点不在 OCR，而在 **OCR 之后的语义层**。

## 5. 技术路径

demo 把链路拆成 6 个可点节点，每步都解释「做了什么 / 为什么」：

1. **检测框**：一图流长边压到 ≤2000px，按 55KB/块上传；OCR 只返回 `x1/y1/x2/y2/text/score`。demo 直接用缓存 dets，不上传原图
2. **锚点聚类**：按 `cy` 聚行，行内取全部命中；weak 与 lev 只补空位，按 `(cy,cx)` 恢复 Z 序
3. **字段归属**：技能框从名字 `cx` 向右 300–440px 归属、半径固定 300px；增益 / 减益是两个独立框；资质串单独取
4. **名字归一**：`exact → fuzzy → shape → prefix`，候选池只取 `_pets.json` 基础名；前缀兜底要求「图鉴名 ≥3 字 + 整框开头 + 未被完整命中」
5. **性格反查**：模板 A 直接读性格名；模板 B 由 `(增益, 减益)` 在 30 条性格表里唯一反查
6. **推荐 + 图鉴**：按最终形态名（同编号别名）查 gradRec；再用名字回链 `_pets.json` 取 `pet_id` / 图鉴编号 / 蛋组 / 性别比例 / 赛季

四个关键判断：

| 判断 | 决策 | 理由 |
|---|---|---|
| 数据边界 | 只消费 dets，不传原图 | 原图含个人信息且体积大；dets 足够完成全部语义链路 |
| 名字真源 | 只用 `_pets.json` 基础名做候选池 | 曾混入 PVP 助手 / 测试名，读图会把队名误认成精灵（「无敌水蓝蓝」） |
| 两条兜底 | weak / lev 只补空位，不插队 | 3 行 2 列里伪行 cy 更小，整体重排会把真名挤出 6 格 |
| 事实与参考分离 | 推荐未命中不改写 OCR 结果 | 推荐可能有多口径（毕业 / 可用 / 收藏），不是唯一真值 |

## 6. 关键技术挑战

1. **2 行 3 列丢列**：旧逻辑每行按 `cx` 升序只取前 2 个，魔力猫 / 罗隐必被丢
2. **跨行串列**：技能框纯右偏，旧对称窗口 `[cx±tol]` 会把上一行技能分给下一行；列距计算被跨行锚点污染后更严重
3. **水印粘连**：「卡瓦重噜球狼王」长度远超图鉴名，长度门禁先拒掉，需要独立的前缀兜底
4. **伪行挤位**：weak 补位里混着「速度魔攻 / 个体资质 / 筛管窝流」，按 cy 整体重排后真名被截掉
5. **性格表达差异**：同一链路要同时支持「直接性格名」与「增益减益反查」两种模板
6. **推荐多口径**：同一最终形态可能有多条性格 / 等级 / 资质组合，需要保留全部行而不是只取一条

## 7. 应对方案

1. 按 `cy` 聚出所有行、行内取整行命中，再按元素数降序拼够 6 格，最后按 `(cy,cx)` 恢复 Z 序
2. `clusterFields` 增加非对称 `cxRight`，半径固定 300px；列距只在行内计算，避免跨行污染
3. 新增 `matchNamePrefix`，要求整框开头命中、图鉴名 ≥3 字、整体未被 exact/fuzzy 命中，取最长匹配
4. weak 先过滤属性串与标签词，再按「含图鉴名子串优先」排序，只补 `need` 个且保留已 picked 真名
5. 30 条性格表由 `性格表.csv` 生成，`(增益, 减益)` 组合唯一，直接命中就用、不猜方向
6. 推荐按「最终形态名 + 同编号别名」查离线缓存，按 `(性格, 等级)` 去重后全部展示，命中项高亮

## 8. 结果与价值

- **识别可见性**：两份真实样本、12 格阵容全部给出「原始文本 → 图鉴真名 → 性格 → 推荐 → pid」完整证据链
- **版式兼容**：2 行 3 列与 3 行 2 列 + 水印粘连都在同一条链路上跑通
- **语义分层**：技能池外的 OCR 文本（如「筛管窝流」）保留原文并标黄，不混进正式技能
- **推荐不越权**：6 格里既有命中也有未命中（如翠顶夫人当前固执、推荐平和），页面如实标注
- **链路复用**：图鉴回链字段（`pet_id` / 蛋组 / 性别 / 赛季）可直接喂给模块 C 蛋窝决策与模块 D 毕业进度

## 9. demo 能力范围

- **入口**：`live.html`，双击即用，零依赖、零外网请求；`data.js` 为脱敏数据
- **样例切换**：「2 行 3 列」与「3 行 2 列 + 水印」两份真实 OCR 缓存
- **6 阶段回放**：从 dets 载入到推荐 / 图鉴回链逐步推进，左侧事件流可展开证据 JSON
- **检测框画布**：按真实 bbox 等比例绘制，不加载原图；选中格的相关文本高亮
- **证据链面板**：每格展示原文、匹配方式、性格来源、资质、技能池标记、推荐行、图鉴字段
- **导出与合规**：可导出整份识别 JSON；「脱敏检查」说明不传原图 / 不带 UID / 不发起外部请求
