# 模块 B 实施计划：阵容识别 → 性格推荐 → 图鉴链路

> 本文件是模块 B 的实施依据：先按计划收敛交互与数据口径，再逐项完成验证清单。
> 同目录下的 `live.html` / `data.js` / `scripts/` 为实现产物，在本轮实现中按此清单完善，不推倒重来。

## 1. 模块定位

- **一句话**：把一图流截图里不可查询的 6 格阵容，变成带证据链的结构化数据，并接上性格推荐与图鉴字段。
- **范围**：从真实 OCR 缓存样本发现版式 / 水印 / 语义问题，完成真源取舍，做成可交互原型。
- **非目标**：不接腾讯云 OCR、不部署云函数、不上传原图、不自动改写识别结果。

## 2. 痛点（基于已确认的真实样本）

- 2 行 3 列样本里，魔力猫 / 罗隐因「每行只取前 2 个」被丢
- 3 行 2 列狼王队里，「卡瓦重噜球狼王」被水印粘连，整名匹配失败
- 「筛管窝流 / 个体资质 / 速度魔攻」等伪行会被 weak 补位挤进 6 格队列
- 性格在同一条链路上有两种表达：直接性格名 vs `(增益, 减益)` 反查
- 读出来的性格还要和 gradRec 多口径推荐比对，人工转录常把两者混为一谈

## 3. 三个关键判断

| 判断 | 决策 | 理由 |
|---|---|---|
| 数据边界 | 只消费 OCR `dets`，不传原图 | 原图大且含个人信息；dets 足够完成全部语义链路 |
| 语义真源 | 名字池只用 `_pets.json` 基础名，技能池只用 `pet_skills.json` | 曾混入队伍名 / 测试名，产生「无敌水蓝蓝」等虚构精灵 |
| 事实与参考分离 | 推荐未命中不改写 OCR 结果 | gradRec 有毕业 / 可用 / 收藏多口径，不是唯一真值 |

## 4. 技术方案（取自上级项目真源）

1. **检测框**：长边 ≤2000px、55KB/块；OCR 输出 `x1/y1/x2/y2/text/score`
2. **锚点聚类**：按 `cy` 聚行 → 行内取全部命中 → weak / lev 只补空位 → 按 `(cy,cx)` 恢复 Z 序
3. **字段归属**：技能框非对称窗口 `[cx-80, cx+colGap×0.8]`、半径 300px；增益 / 减益独立框；资质串单独取
4. **名字归一**：`exact → fuzzy → shape → prefix`；前缀兜底要求图鉴名 ≥3 字 + 整框开头 + 未被完整命中
5. **性格反查**：`(增益, 减益)` 在 30 条唯一性格表里反查；直接读到性格名则跳过
6. **推荐 + 图鉴**：按最终形态名（同编号别名）查 gradRec；`name → pet_id` 回链蛋组 / 性别 / 赛季

关键真源：`scripts/testdata/ocr_real_sample_3col.json`、`ocr_real_sample_wolf.json`、`scripts/selftest_teamocr.js`、`cloudfunctions/teamOcr/natures.js` / `pool_names.json` / `pool_skills.json`、`dashboard/grad_rec.json.bare_bak`、`dashboard/_pets.json`。

## 5. Demo 设计

- **形态**：`live.html` 单文件（内联 CSS/JS）+ `data.js`，双击打开即用
- **交互组件**：
  - 两份样例切换（2 行 3 列 / 3 行 2 列 + 水印）
  - 6 步链路节点，点击展开「做了什么 / 为什么」
  - 「开始识别」按阶段推进，左侧事件流按阶段输出证据
  - 检测框画布按真实 bbox 等比例绘制；选中格相关文本高亮
  - 右侧证据链：原文 → 真名 → 性格 → 技能池标记 → 推荐行 → 图鉴字段
  - 六格结论表可点选；导出 JSON；脱敏检查弹窗
- **视觉**：深色科技感 + 紫粉渐变，与模块 A 同一套 token
- **不做**：真实 OCR 调用、云函数、上传原图、自动改写识别值

## 6. 数据方案

- 源：上级项目两份真实 OCR 缓存 + 真源表 + gradRec 离线缓存
- 脱敏：不含原图、玩家昵称、UID、设备 IP、精确时间戳；只保留 dets 与字段值
- 生成：`scripts/prepare_team_data.py` 输出 `window.TEAM_DEMO_DATA`，可重跑；断言性格表 30 条、图鉴条目存在
- 推荐别名：`圣剑-X` ↔ 推荐表 `X_圣剑`，同为图鉴编号 286，在脚本里显式登记
